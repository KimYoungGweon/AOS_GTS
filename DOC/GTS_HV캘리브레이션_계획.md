# AOS HV / CV 자동 캘리브레이션 — 사양 및 계획

작성 2026-09-24 · 김영권 설명 + STM32H753 F/W 코드(`DOC/AOS_H753_V1_Single`) 분석 기반
회사에서 DMM 연결 후 새 세션으로 착수

> 표기: **✔ 확정**(설명받았거나 코드로 확인) / **❓ 확인 필요**

---

## 1. 목적

- AOS 의 HV·CV 출력과 HV 측정값을 Keysight DMM 으로 자동 보정한다.
- 현재: F/W 소스에 SN 별로 **15~26 포인트를 손으로 입력** (`CAL_CTL.c` `Set_Cal_Default_Factor_*`) ✔
- 이번: 테이블 최대 **40 → 101 포인트**로 늘리고 자동 측정·저장 ✔
- 대상 3 가지: **HV_DAC, HV_ADC, CV_DAC** ✔ (FAN_VS, ION_BIAS, HV_IS 등 다른 파라미터는 이번 범위 밖)

## 2. 보정 대상

|---|---|---|---|---|---|---|
| 1 | **HV_DAC** | LTC2602 **ch1**, 16 bit | 0 ~ 200 V ✔ | `CSET` | 실측 전압 (float) | DAC (u16) |
| 2 | **HV_ADC** | AD7739 **ch0** (`HV_Vs_adc`, u16) | 0 ~ 200 V zsh -n ~/Git_Repository/AOS_GTS/tools/gts_env.zsh && exec zsh| `CSENSE_VS` | ADC raw (u16) | 실측 전압 (float) |
| 3 | **CV_DAC** | LTC2602 **ch0**, 16 bit | −5 ~ +5 V ✔ | `CSET_CV` | 실측 전압 (float) | DAC (u16) |

- CV 는 ADC 없음 ✔
- F/W 는 테이블 사이를 **구간 선형 보간**, 양 끝 밖은 끝 구간 기울기로 외삽 ✔ → **X 는 오름차순**이어야 함
- HV 최대 전압: 초기 개발 때 560 V → **현재 200 V 로 축소** ✔
  - 소스의 SN 0~3 기본 테이블(~560 V)은 초기 개발 시절 값 → 200 V 장비에는 그대로 쓰지 않음
  - HV 상한 관련 상수·클램프(DAC 식 `65536/200`, 서버/F/W 상한)도 200 V 기준으로 통일

## 3. 보정 방식

공통: **정해진 DAC 값을 출력 → DMM 실측 기록** ✔ (DAC 를 목표 전압에 맞춰 반복 조정하지 않음)

### 3.1 HV_DAC

- 정해진 DAC 값 ✔: `DAC = 65536 / 200 × X − 1` (X = 공칭 전압 0~200 V, 0 미만은 0 으로)
- 101 스텝이면 2 V 간격 → DAC 654, 1309, … 65535
- **30 V 이하는 보정 불가** ✔ → 시작점을 점프
  - 기존 테이블도 같은 방식: `(0 V, 0)` → `(51.2 V, 1)` → `(52.4 V, 4726)` … 처럼 **첫 포인트 뒤 바로 출력 가능 영역으로 점프**
- 스텝마다 기록: `(DMM 실측 V, DAC)` → `CSET.X / CSET.Y`

30 V 이하 처리 ✔ — **2 V 격자 유지: `0 V` + `30, 32, … 200 V` = 87 포인트**

| 포인트 | 공칭 V | DAC |
|---|---|---|
| 1 | 0 | 0 |
| 2 | 30 | 9829 |
| 3 | 32 | 10485 |
| 4 | 34 | 11140 |
| … | … | … |
| 87 | 200 | 65535 |

- 30 V 에서도 출력이 안 나오는 장비는 **HW 를 조정해서 해결** ✔ — S/W 에서 건너뛰기 규칙은 두지 않음.
  자동 보정은 이상 감지 시 중단하고 알리기만 함 (HW 조정 후 재시도)

### 3.2 HV_ADC

- HV_DAC 와 **같은 스윕에서 동시 수집** 가능: DAC 출력 → DMM 실측 + `HV_Vs_adc` 읽기 → `(ADC raw, 실측 V)`
- 30 V 이하 점프도 비슷 ✔ (기존: `(0, 0 V)` → `(347, 50.8 V)` …) → HV_DAC 와 같은 **87 포인트** (0 V + 30~200 V)
- ❓ 설명 이어서 받을 부분 (메시지 중단됨)

### 3.3 CV_DAC

- −5 ~ +5 V, 정해진 DAC 값 → DMM 실측 ✔
- **100 스텝 (−5.0 ~ +5.0 V, 0.1 V 간격) = 101 포인트** ✔ → `CAL_NO 101` 에 딱 맞음
- DAC 식 (HV 와 같은 형태로 가정 ❓): `DAC = 65536 / 10 × (X + 5) − 1` (0~65535 로 클램프)

| 포인트 | 공칭 V | DAC |
|---|---|---|
| 1 | −5.0 | 0 |
| 2 | −4.9 | 654 |
| … | … | … |
| 50 | −0.1 | 32112 |
| 51 | 0.0 | 32767 |
| 52 | +0.1 | 33422 |
| … | … | … |
| 101 | +5.0 | 65535 |

- 기존 테이블의 0 V 부근 DAC(32762~32898)와 식이 잘 맞음 → 식은 이대로 가도 될 것으로 보임 ❓
- 기존 테이블은 ±0.5 V 부근을 더 촘촘히(0.02~0.05 V) 잡았으나, 이번에는 0.1 V 균일 간격으로 결정 ✔

### 3.4 범위·간격은 사용자가 조절 ✔

위 87 / 101 포인트는 **기본값**이고, 웹 화면에서 사용자가 바꿀 수 있어야 함.

| 항목 | HV (DAC·ADC) 기본값 | CV 기본값 | 제약 |
|---|---|---|---|
| 0 V 기준점 포함 | 예 (0 V, DAC 0) | — | HV 전용 |
| 시작 전압 | 30 V | −5.0 V | HV ≥ 0, CV ≥ −5 |
| 끝 전압 | 200 V | +5.0 V | HV ≤ 200, CV ≤ +5 |
| 간격 | 2 V | 0.1 V | |
| → 포인트 수 | 87 | 101 | **F/W 테이블 최대 101 이하** (넘으면 화면에서 막음) |

- 화면에서 설정값으로 계산한 **포인트 수·DAC 목록을 미리 보여 주고** 시작
- 설정값은 장비 SN 별로 서버에 저장해 다음 보정 때 기본값으로 불러옴 ❓

### 3.5 일부 구간 보정 ✔

전체를 다시 하지 않고 **지정한 구간만** 다시 측정해서 기존 테이블에 합친다. (예: HV 150~200 V 만, CV −1~+1 V 만)

1. `CMD_CAL_QUERY` 로 현재 F/W 테이블을 읽어 서버에 백업
2. 사용자가 지정한 구간(시작·끝·간격)만 측정
3. 합치기: 기존 테이블에서 **구간 안의 포인트는 삭제**하고 새 측정값으로 교체, 구간 밖은 유지
4. X 오름차순 정렬 → 역전(단조성 깨짐) 검사 → 포인트 수 ≤ 101 확인
5. 화면에 **기존 / 새 테이블 비교** (그래프 + 표) → 사용자 확인 후 `CMD_CAL_WRITE`

❓ 경계 처리: 구간 양 끝에서 기존 포인트와 새 포인트가 너무 가깝거나 어긋나면(단차) 경고할지

### 3.6 보정 결과 검증 ✔

보정 테이블을 저장한 뒤 **보정된 경로로** 실제 정확도를 확인한다. 보정 직후뿐 아니라 **언제든 단독 실행** 가능 (정기 점검용).

| 대상 | 방법 | 비교 |
|---|---|---|
| HV_DAC | `CMD_SET_Volt(V)` — F/W 가 보정 테이블로 DAC 계산 | 설정 V vs DMM 실측 |
| HV_ADC | 같은 상태에서 `CMD_STATUS_QUERY` 의 `HV_Vs` (보정된 값) | F/W 표시 V vs DMM 실측 |
| CV_DAC | `CMD_CV_SET(V)` | 설정 V vs DMM 실측 |

- 검증 포인트는 보정 포인트와 **다른 값**(예: 보정 포인트 사이 중간값)도 넣을 수 있게 → 보간 오차까지 확인
- 검증 범위·간격도 사용자 조절
- 결과: 포인트별 오차(V, %) 표 + 그래프, 최대·평균 오차
- **합격/불합격은 당분간 사용자가 판정** ✔ — 자동 허용 오차 기준은 두지 않음. 화면에 합격/불합격 버튼 + 메모 입력
  (나중에 데이터가 쌓이면 자동 기준 추가 검토)
- 불합격 구간이 있으면 → 그 구간만 **3.5 일부 구간 보정**으로 바로 연결
- 검증 결과·판정·메모를 SN·일시와 함께 서버에 기록

### 3.7 장비별 결과 비교 ✔

장비별 편차가 중요하므로, 보정·검증 결과를 **SN 끼리 겹쳐서 비교**할 수 있어야 함.

- 서버 DB 에 SN 별 이력 저장: 보정 원시 데이터(DAC·ADC·DMM), 최종 테이블, 검증 결과, 판정, 메모, 일시
- 비교 화면 (여러 SN 선택)
  - HV_DAC: 공칭 V → 실측 V 곡선 겹쳐 보기 / 공칭 대비 편차(V, %) 곡선
  - HV_ADC: ADC raw → 실측 V 곡선 / 편차
  - CV_DAC: 같은 방식, 0 V 부근 확대
  - 요약 표: SN 별 기울기·오프셋(1 차 근사), 최대 편차, 출력 시작 전압, 검증 최대 오차
- 같은 SN 의 **시간에 따른 변화**(재보정 이력)도 겹쳐 보기 → 드리프트 확인
- CSV 내보내기 (엑셀로 추가 분석)
- ❓ 비교 기준선: 공칭 식(`65536/200×X−1` 등) 대비로 볼지, 특정 기준 장비 대비로 볼지 — 둘 다 선택 가능하게

## 4. F/W 코드 분석 결과 — 101 스텝을 위해 고칠 것

### 4.1 반드시 수정

| # | 위치 | 현재 | 문제 / 조치 |
|---|---|---|---|
| 1 | `CAL_CTL.h` | `#define CAL_NO 40` | **101 로 변경**. RAM 은 테이블당 ~610 B 라 문제 없음 |
| 2 | `CAL_CTL.c` EEPROM 주소 | 테이블 간격 0x200 (512 B) | 101 포인트 = `1 + 101×6 = 607 B` 로 **다음 테이블을 침범**. 예: HV_VS 0x0600 → 0x085E 가 HV_IS 0x0800 을, CV_DAC 0x0A00 → 0x0C5E 가 FAN_VS 0x0C00 을 덮음 → **주소 재배치 필요** (0x1000 SHALLOW_2D, 0x4000 HMAP_CFG 피해서) |
| 3 | `MyCTL.c` `System_Init()` | 부팅 때마다 `Set_Cal_Default_*()` → `CAL_Data_Write(0..5)` → `CAL_Data_Read(0..5)` | **EEPROM 의 보정값을 매 부팅 소스 기본값으로 덮어씀** → 자동 보정해서 저장해도 재부팅하면 사라짐. **EEPROM 먼저 읽고, 유효하면 사용 / 무효면 기본값** 으로 변경 (No 범위 2~101 체크 + magic/CRC 권장) |
| 4 | UART 명령 | DAC raw 설정·ADC raw 읽기 명령 없음 | `CMD_SET_Volt` 는 이미 보정 테이블을 거쳐 DAC 를 계산하고, `CMD_STATUS_QUERY` 는 보정된 `HV_Vs`(float)만 줌. 현재 raw ADC 는 조그로 `Cal_Mode` 켜서 LCD 로만 봄 → **신규 명령 추가 필요** (아래 4.3) |

### 4.2 버그 (이번에 같이 수정 권장)

| # | 위치 | 내용 |
|---|---|---|
| 5 | `CAL_Data_Write()` case 4 (CV_DAC) | **`break` 누락** → CV 저장 시 case 5(BIAS_VS)까지 같이 씀 |
| 6 | `HV_SET_Control()` 램프 | `tVolt += (i+1)*HV_Step` → 30, 60, 90 V 씩 **누적 증가해 목표를 넘을 수 있음**. `tVolt += HV_Step` 이 의도로 보임. 고압 안전 관련 |
| 7 | `Parameter_Set_Control(hv, frq, duty, cv)` | 인자 이름이 뒤바뀜 (`hv` → CV DAC, `cv` → HV DAC). 호출부 확인 필요 ❓ |

### 4.3 신규 UART 명령 제안 (번호 ❓, 기존 0xA0~0xA3 옆)

| 명령 | 방향 | payload | 동작 |
|---|---|---|---|
| `CMD_CAL_DAC_RAW_SET` | PC → F/W | `u8 ch` (0=CV, 1=HV), `u16 dac` | 보정 테이블 없이 `LTC2602_COMMAND(ch, dac)` 직접 출력. HV 는 F/W 에서도 상한·램프 적용 |
| `CMD_CAL_ADC_RAW_QUERY` | PC → F/W | `u8 ch`, `u8 avg_n` | `AD7739_READ(ch)` n 회 평균 raw 회신 (u16 또는 u32) |
| (기존) `CMD_CAL_WRITE` 0xA0 | PC → F/W | `u8 type, u8 No, No × {X, Y}` | RAM 반영 + EEPROM 기록 + 재읽기. 101 포인트 = 608 B < `CMD_QUEUE_SIZE` 4096 ✔ |
| (기존) `CMD_CAL_QUERY` 0xA1 | PC → F/W | `u8 type` | 테이블 회신 (`SOut` 4010 B 안 ✔) |

CAL type ✔: `0=HV_DAC, 1=HV_VS(ADC), 2=HV_IS, 3=FAN_VS, 4=CV_DAC, 5=BIAS_VS`

### 4.4 UART 프레임 ✔ (`UART_PC.c`)

```
0x02 | CMD | LEN_L | LEN_H | DATA[LEN] | CS
CS = 0xFF − (CMD + LEN_L + LEN_H + ΣDATA) & 0xFF      (= ~sum)
다바이트 값은 little-endian (float 4B, u16 2B)
```

## 5. 측정 구성

```
[브라우저] ─HTTP─▶ [GTS 서버 192.168.0.6] ─TCP 5025 / SCPI─▶ [Keysight DMM]
                          │
                          └─(경로 ❓)─▶ [AOS STM32H753 UART_PC]
                                         LTC2602 ch1 → HV P/S,  ch0 → CV
                                         AD7739 ch0 ← HV 분압
```

- DMM: Keysight 34410A 계열 ❓ (`*IDN?` 로 확인). 기존 C# 은 IO Libraries + USB/GPIB ✔
- 웹 방식: 서버가 LAN SCPI(TCP 5025)로 DMM 제어, IO Libraries 불필요. 명령 끝 `\n`, 동시 접속 1개
- DMM 레인지: HV → 1000 V 레인지(200 V 초과 대비) 또는 AUTO ❓, CV ±5 V → 10 V 레인지
- ❓ 서버 ↔ AOS 경로: `gts_aos_bridge`(UDP) 경유 / 시리얼 직결 / 기존 C# 방식
- ❓ DMM 을 HV 출력에 직결하는지, 부하 조건

## 6. 자동 보정 흐름 (안)

```
1. 사전 확인: 배선·부하, DMM *IDN?, AOS 연결, 현재 테이블 백업 (CMD_CAL_QUERY → 서버 저장)
2. HV 스윕 (HV_DAC + HV_ADC 동시)
   for DAC in 정해진 DAC 목록 (30 V 이하 점프):
       CMD_CAL_DAC_RAW_SET(1, DAC)          ← 서버에서 램프 (한 번에 큰 폭 금지)
       안정화 대기 ❓
       DMM READ? (n 회 평균 ❓)  → V_real
       CMD_CAL_ADC_RAW_QUERY(0, n) → adc
       기록 (V_real, DAC), (adc, V_real);  이상값이면 중단 → 0 V
   → 0 V 로 복귀
3. CV 스윕: CMD_CAL_DAC_RAW_SET(0, DAC) → DMM → (V_real, DAC)
4. 테이블 정리: X 오름차순 정렬, 중복·역전 제거, 포인트 ≤ 101
5. CMD_CAL_WRITE (type 0, 1, 4) → CMD_CAL_QUERY 로 되읽어 비교
6. 검증 (3.6): CMD_SET_Volt / CMD_CV_SET / HV_Vs → DMM 오차 표시, 불합격 구간은 일부 구간 보정(3.5)으로
7. 결과를 서버 DB/CSV 에 기록 (장비 SN, 일시, 스텝 수, DMM 정보, 원시 데이터)
```

## 7. 안전

- HV 상한(200 V)·CV 상한(±5 V)을 **서버와 F/W 양쪽에서** 강제
- 램프: 서버에서 스텝 간격 제한 + F/W 램프 버그(4.2 #6) 수정
- 비상 정지 → 즉시 DAC 0
- DMM 무응답, 설정 대비 편차 과다, ADC 역전 시 자동 중단 → 0 V
- 종료·중단 시 항상 0 V, 방전 대기 ❓
- 시작 전 확인 절차(배선·부하)

## 8. 확인 필요 목록

1. (확정) HV 최대 200 V
2. (확정) 30 V 이하 점프: 0 V + 30~200 V 2 V 간격 = 87 포인트(기본값, 사용자 조절). 30 V 출력 불가 장비는 HW 조정
3. **나중에** — HV_ADC 평균 횟수 등 세부 (회사에서 실측하며 결정)
4. (확정) CV 100 스텝 0.1 V. DAC 식 `65536/10×(X+5)−1` 확인만 필요
5. 서버 ↔ AOS 통신 경로
6. 안정화 대기 시간, 평균 횟수, DMM NPLC
7. 신규 UART 명령 번호, EEPROM 새 주소 배치, EEPROM 용량(칩 종류)
