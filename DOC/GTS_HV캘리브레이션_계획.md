## 1. 목적

- AOS 의 HV·CV 출력과 HV 측정값을 Keysight DMM 으로 **웹에서 자동 보정**
- 대상 3 가지 ✔: **HV_DAC, HV_ADC, CV_DAC** (FAN_VS, ION_BIAS, HV_IS 등은 범위 밖)
- 테이블 최대 **101 포인트** ✔ (기존 수동 입력 15~40 포인트)
- 합격/불합격은 **당분간 사용자 판정** ✔, **장비(SN)별 결과 비교** 필수 ✔

## 2. 보정 대상

| # | 대상 | 하드웨어 | 전체 범위 ✔ | 테이블 X → Y | F/W 테이블 / CAL type |
|---|---|---|---|---|---|
| 1 | **HV_DAC** | LTC2602 ch1, 16 bit (0~65535) | 0 ~ 200 V | 실측 V (float) → DAC (u16) | `CSET` / 0 |
| 2 | **HV_ADC** | 현재 AD7739 ch0 16 bit / 새 보드 MCP3202 12 bit (0~4095) | 0 ~ 200 V | ADC raw (u16) → 실측 V (float) | `CSENSE_VS` / 1 |
| 3 | **CV_DAC** | LTC2602 ch0, 16 bit (0~65535) | −5 ~ +5 V | 실측 V (float) → DAC (u16) | `CSET_CV` / 4 |

- CV 는 ADC 없음 ✔
- 보정 방식 ✔: **정해진 DAC 값을 출력 → DMM 실측 기록** (반복 조정하지 않음)
- F/W 는 구간 선형 보간, 양 끝 밖은 끝 구간 기울기로 외삽 → **X 오름차순** 필요
- HV 최대: 초기 560 V → **현재 200 V** ✔
- **ADC 비트 수는 장비(보드) 설정값**으로 둔다 — 16 bit / 12 bit 에 따라 초기화 테이블, raw 범위, 해상도 표시가 달라짐
  - 12 bit 에서 200 V 풀스케일이면 1 LSB ≈ 49 mV → ADC 평균 횟수가 더 중요해짐 ❓

## 3. 캘리브레이션 절차

```
① 초기화  →  ② 수동 조작으로 범위 결정  →  ③ 자동 측정  →  ④ EEPROM 저장  →  ⑤ 검증  →  ⑥ 기록·비교
```

### 3.1 ① EEPROM 보정 테이블 초기화 ✔

캘리브레이션 전에 이전 보정값의 영향을 없애기 위해 **2 포인트 선형 기본값**으로 되돌린다.

| 대상 | 초기화 테이블 (X → Y) |
|---|---|
| HV_DAC | `0 V → 0`, `200 V → 65535` |
| HV_ADC | `0 → 0 V`, `65535 → 200 V` (16 bit). **MCP3202 보드는 `4095 → 200 V`** ❓ |
| CV_DAC | `−5 V → 0`, `+5 V → 65535` |

- 초기화 **직전에 현재 테이블을 읽어 서버에 백업** (되돌리기 가능하게)
- 초기화 후에는 전압 설정이 곧 공칭 DAC 가 됨:
  HV `DAC ≈ 65535/200 × V`, CV `DAC ≈ 65535/10 × (V+5)`,
  ADC raw 는 표시값에서 역산 가능 (`raw ≈ HV_Vs × FS/200`)
  → **전체 보정은 기존 전압 설정(브리지 0x40)·상태 조회만으로 가능** (5.1). raw 명령은 일부 구간 보정용

### 3.2 ② 수동 조작으로 범위 결정 ✔

웹 화면에서 HV / CV 를 **직접 조금씩 움직이면서** DMM 실측을 보고 쓸 수 있는 최소·최대를 정한다.
(예: HV 가 실제로 출력되기 시작하는 전압, 포화되는 전압)

화면 구성 (목업 5-2):
- 출력 설정: 전압 입력 + 미세 조정 버튼(±0.1 / ±1 / ±10 V, CV 는 ±0.01 / ±0.1 / ±1 V)
- 실시간 표시: 설정값, DAC, **DMM 실측**, HV ADC raw, 편차
- 버튼: **[이 값을 최소로]**, **[이 값을 최대로]**, **[현재 점 기록]**, **[0 V 로 복귀]**
- 결정된 범위 + 간격 → **포인트 수·DAC 목록 미리보기** (최대 101, 넘으면 시작 불가)

범위·간격 기본값 (사용자 변경 가능) ✔

| 항목 | HV (DAC·ADC) | CV |
|---|---|---|
| 0 V 기준점 포함 | 예 (0 V, DAC 0) | — |
| 최소 | 수동으로 결정 (참고: 이전 장비 30~51 V) | 수동으로 결정 (기본 −5.0 V) |
| 최대 | 수동으로 결정 (≤ 200 V) | 수동으로 결정 (기본 +5.0 V) |
| 간격 | 2 V | 0.1 V |
| 포인트 수 | 범위에 따라 (≤ 101) | 범위에 따라 (≤ 101) |

- 출력이 너무 늦게 시작하는 장비는 **HW 조정으로 해결** ✔ (S/W 에서 건너뛰지 않음)
- 결정한 범위는 SN 별로 서버에 저장 → 다음 보정 때 기본값 ❓

### 3.3 ③ 자동 측정 ✔

```
for DAC in 범위 안의 정해진 DAC 목록:
    DAC 출력                        ← 서버에서 램프 (한 번에 큰 폭 금지)
    안정화 대기 ❓
    DMM READ? (n 회 평균 ❓)  → V_real
    (HV 일 때) ADC raw (n 회 평균 ❓) → adc
    기록 (V_real, DAC), (adc, V_real)
    이상(DMM 무응답·편차 과다·역전·브리지 무응답) → 중단, 0 V
끝 → 0 V
```

- HV_DAC 와 HV_ADC 는 **같은 스윕에서 동시 수집**
- 0 V 기준점: HV 는 `(0 V, DAC 0)` / `(ADC 0, 0 V)` 를 테이블 첫 포인트로 넣어 "시작점 점프"를 표현 (기존 방식과 동일)
- CV 는 별도 스윕 — HV 스윕 뒤 0 V·방전 대기 → **DMM 을 CV 출력으로 옮기라는 안내** → 사용자 확인 후 진행

### 3.4 ④ F/W EEPROM 저장 ✔

1. 테이블 정리: X 오름차순, 중복·역전 제거, 포인트 ≤ 101
2. 화면에 **이전(백업) / 새 테이블 비교** (그래프 + 표) → 사용자 확인
3. F/W 에 전송 (`CMD_CAL_WRITE` type 0·1·4) → EEPROM 기록 → **`CMD_CAL_QUERY` 로 되읽어 비교**
4. 재부팅 후에도 유지되는지 확인 — **현재 F/W 는 부팅 때 기본값으로 덮어씀** (4.1 #3, F/W 수정 필수)

### 3.5 일부 구간 보정 ✔

지정한 구간만 다시 측정해서 기존 테이블에 합친다 (예: HV 150~200 V).
- 이 경우 **① 초기화는 하지 않음** — 기존 테이블을 유지해야 하므로 → 보정 테이블을 거치지 않는 **raw DAC 출력 명령 필요** (4.3)
- 구간 안의 기존 포인트는 삭제 후 교체, 구간 밖 유지 → 정렬·역전 검사 → 비교 화면 → 저장
- ❓ 경계에서 기존·새 포인트 단차가 크면 경고

### 3.6 ⑤ 검증 ✔

저장한 테이블로 **보정된 경로**의 정확도를 확인. 보정 직후 + 언제든 단독 실행 (정기 점검).

| 대상 | 방법 | 비교 |
|---|---|---|
| HV_DAC | 전압 설정 (F/W 가 테이블로 DAC 계산) | 설정 V vs DMM |
| HV_ADC | 같은 상태에서 F/W 표시 HV_Vs | 표시 V vs DMM |
| CV_DAC | CV 설정 | 설정 V vs DMM |

- 보정 포인트 사이 중간값도 검증 (보간 오차 확인), 범위·간격 사용자 조절
- 결과: 포인트별 오차(V, %) + 그래프, 최대·평균
- **합격/불합격 버튼 + 메모** (사용자 판정) ✔
- 불합격 구간 → 3.5 일부 구간 보정으로 연결

### 3.7 ⑥ 기록·장비별 비교 ✔

- 서버 DB 에 SN 별 이력: 백업 테이블, 수동 결정 범위, 원시 데이터(DAC·ADC·DMM), 최종 테이블, 검증 결과, 판정, 메모, **ADC 종류(AD7739/MCP3202)**, DMM 정보, 일시
- 비교 화면 (여러 SN 선택): 곡선 겹쳐 보기 / 편차 곡선 / 요약 표(기울기·오프셋, 최대 편차, 출력 시작 전압, 검증 최대 오차)
- 같은 SN 재보정 이력 겹쳐 보기 (드리프트)
- ADC 비트 수가 다른 장비끼리 비교할 때는 raw 대신 **실측 V 기준**으로 정규화
- CSV 내보내기
- ❓ 기준선: 공칭 식 대비 / 기준 장비 대비 (둘 다 선택 가능)

### 4.3 UART 명령

```
0x02 | CMD | LEN_L | LEN_H | DATA[LEN] | CS
CS = ~(CMD + LEN_L + LEN_H + ΣDATA) & 0xFF,  little-endian (float 4B, u16 2B)
CAL type: 0=HV_DAC, 1=HV_VS(ADC), 2=HV_IS, 3=FAN_VS, 4=CV_DAC, 5=BIAS_VS
```

| 명령 | 방향 | payload | 비고 |
|---|---|---|---|
| (기존) `CMD_CAL_WRITE` 0xA0 | → F/W | `u8 type, u8 No, No × {X, Y}` | 101 포인트 = 608 B |
| (기존) `CMD_CAL_QUERY` 0xA1 | → F/W | `u8 type` | 테이블 회신 |
| (신규) `CMD_CAL_DAC_RAW_SET` ❓번호 | → F/W | `u8 ch (0=CV,1=HV), u16 dac` | 테이블 없이 출력. **메인 루프 `SET_Control()` 이 덮지 않게 cal 모드 플래그**, 해제 시 OSET 무효화로 재적용 |
| (신규) `CMD_CAL_ADC_RAW_QUERY` ❓번호 | → F/W | `u8 ch, u8 avg_n` | raw 평균 회신 (AD7739 / MCP3202 공통) |

- HV_Vs(보정된 값) 는 STM32 `0x03` 상태 (자동 송신 25 ms) 에 들어 있음 (UART_PC.c:812)

### 5.1 브리지 경유에 따른 작업 (`gts_aos_bridge`, `DOC/GTS_AOS_Bridge.md`)

현재 브리지는 콘솔 Manual 7 파라미터(0x40~0x45)만 중계한다. 캘리브레이션에 필요한 것:

| # | 항목 | 현재 | 조치 |
|---|---|---|---|
| 1 | 보정 테이블 쓰기/읽기 | 없음 | 신규 UDP 명령 (0x46~0x4E 대역 ❓) → UART `0xA0` / `0xA1` 로 변환, 응답을 UDP 로 되올림 |
| 2 | 버퍼 크기 | `AOS_MAX_FRAME 512` (UDP), `AOS_UART_DATA_MAX 256` (UART) | 101 포인트 테이블 608 B 가 **둘 다 초과** → 1024 로 확대 (또는 분할 전송) |
| 3 | HV_Vs | STATUS(0x45) 에 전류 4 채널만 | STM32 `0x03` 의 `HV_Vs` 를 STATUS 에 추가 (또는 전용 응답) — ADC 수집·검증에 필요 |
| 4 | 섀도 재전송 | 콘솔 0x40 이 오면 100 ms 뒤 `0x2A` 로 HV/FRQ/DUTY/CV 전부 전송 | **cal 모드**: 서버가 해당 AOS 의 콘솔 제어를 막고, 브리지도 섀도 flush 중지 (raw 출력이 `0x2A` 로 덮이지 않게). 끝나면 `0x02` 로 재동기 |
| 5 | raw DAC / ADC | 없음 | 4.3 신규 F/W 명령이 생기면 같은 방식으로 UDP 명령 추가 (일부 구간 보정용) |
| 6 | 안전 | UART 경로에서 **브리지 clamp 가 유일한 방어선** (STM32 `0x2A` 는 memcpy 만) | raw DAC 명령에도 브리지에서 상한·한 번에 바꿀 폭 제한 |
| 7 | UART 대역 | `0x03` 자동 상태가 25 ms 마다 흐름 (38400 bps 공유) | 요청/응답을 CMD 로 구분, 테이블 전송(≈160 ms) 타임아웃 여유 |

- **전체 보정 경로 (raw 명령 없이)**: 선형 초기화(0xA0 2 점) → 0x40 PARAM_SET 으로 HV/CV 설정 = 공칭 DAC 출력 → DMM + HV_Vs 역산 raw → 0xA0 저장
  - 단, HV 설정은 F/W `HV_SET_Control()` 램프를 거침 → 4.2 #6 램프 버그 수정 필요
- 일부 구간 보정은 초기화를 못 하므로 raw DAC 명령(4.3)이 있어야 함

## 6. 안전

- HV 상한 200 V, CV ±5 V 를 **서버·브리지·F/W** 에서 강제
- 수동 조작 화면에도 같은 상한 + 한 번에 바꿀 수 있는 최대 폭 제한
- 램프: 서버에서 스텝 제한 + F/W 램프 버그 수정 (4.2 #6)
- 비상 정지 → 즉시 0 V, 종료·중단 시 항상 0 V, 방전 대기 ❓
- DMM 무응답, 브리지·UART 무응답, 설정 대비 편차 과다, ADC 역전 시 자동 중단 → 0 V
- 캘리브레이션 중에는 콘솔·웹 장비 상세의 해당 AOS 제어를 막음 (제어권)
- 초기화(①) 후에는 보정이 없는 상태이므로 **실제 출력이 설정과 다를 수 있음** → 수동 조작 시 DMM 값을 기준으로 판단
