# GTS / GFC — ESP32 UDP 전환 프로젝트 인수인계 문서

> **이 문서의 목적**
> 다른 프로젝트·세션에서 작업을 이어받기 위한 **단일 진입점(handoff) 문서**다.
> 이 파일 하나만 읽어도 지금까지의 결정·근거·산출물·남은 일을 파악할 수 있도록 작성했다.
> 상세 규격은 같은 폴더의 두 문서를 참조한다.

- 작성일: 2026-09-21
- 대상 프로젝트: `Gas_Flow_CTL` (폴더 `GasFlowerControl`) → **GFC (Gas Flow Controller)**
- 상위 프로젝트: AOS_GTS_Project / `protocol 정리`

---

## 0. 30초 요약

기존 **PC(C# WinForms) ↔ RS232 ↔ STM32 보드** 구조를,
**서버 ↔ UDP ↔ ESP32 ↔ UART ↔ STM32 보드** 구조로 바꾸는 작업이다.
최종적으로는 STM32 를 제거하고 **ESP32 단독**으로 간다.

- **STM32 펌웨어는 변경하지 않는다** — UART 는 현행 `0x70/0x71/0x72`, 1byte SIZE, `255-합` 체크섬 그대로
- **UDP 는 새 바이너리 규격** — `0x30~0x3A`, 2byte SIZE, CRC16-MODBUS, Device Type + Device ID, 실수는 4byte float
- 변환은 전부 **ESP32 가 담당**한다
- 가스 제어의 핵심 설정값은 **초기 주입시간(`init_on_sec`)** 과 **10분 주기 주입시간(`cycle_on_sec`)** 두 개다
- 목표농도 자동추종은 응답이 매우 느려 난이도가 높다 → **개루프(고정 주입) 우선, 예측형 On/Off 까지가 1차 범위**

## 2. 기존 시스템 분석 (작업의 출발점)

### 2.1 기존 PC 프로그램 구조 (`Gas_Flow_CTL`, C# .NET Framework 4.8)

| 파일 | 역할 |
|---|---|
| `MyCTL/mRS232.cs` | RS232 통신 계층 — 프레임 송수신, 상태머신 파서, 체크섬, 명령 코드 정의 |
| `MyCTL/mStruct.cs` | 데이터 구조체 (`__gasflow`), 설정 상수 (`cConf`) |
| `MyCTL/mFile.cs` | 로그 저장/불러오기 |
| `sMain_GasFlow.cs` | 수신 스레드, 그래프, 주입 제어, 자동 농도조절, UI 생성 |
| `frmMain.cs` | 폼 이벤트 핸들러, 10ms 타이머 |

### 2.2 기존 동작에서 파악한 핵심 사실

1. **장비가 약 5초 주기로 `0x72` 프레임을 자동 push** 한다.
   PC 코드의 `GasFlow_Status_Query()` / `GasFlow_Pump_Query()` 는 **정의만 되어 있고 호출부가 없다.**
   → 자동 송신에 전적으로 의존하는 구조. (ESP32 에서는 이 점을 보완 — FR-2)
2. TVOC 값은 SGP30 ppb 가 아니라 **12bit ADC raw** 이며, `raw * 5.0 / 4095` 로 전압 환산한다.
   주석상 2026-07-18 에 3.3V → 5.0V 기준으로 변경된 이력이 있다.
3. `0x72` 응답 11 byte 중 offset 3~4 / 7~8 의 2바이트 2쌍은 **파싱에서 건너뛴다** (eCO2 로 추정, 미확인).
4. 송신 시 `Pump[2] = Pump[1]` 로 덮어써서 **Pump3 는 항상 Pump2 를 따라간다.**
5. 자동 농도조절은 **EMA(0.8/0.2) + 60초 창 기울기 + 예측 선행시간(120초) + 히스테리시스(0.05V)** 방식.
6. Source 주입은 10분 주기, 주기당 0.1~600초 On. Pump1 은 시작 시 항상 On.
7. Pump2 Off 시점에 `(On 시작시각, 유지시간)` 을 `_pump.dat` 에 기록해 구형파 그래프를 복원한다.

| # | 결정 | 근거 | 상태 |
|---|---|---|---|
| D1 | FAIMS 공용 명령(RF Amp / CV / Scan / Shallow / Cal, `0x00~0x63`, `0xA2~0xA3`) 문서에서 제외 | GFC 장비와 무관 | 확정 |
| D2 | ~~UART 명령 `0x70→0x30` 재배정~~ → **취소, 현행 유지** | **기존 STM32 코드를 변경하지 않기로 함** | 확정(번복) |
| D3 | 상위 링크를 PC(RS232) → ESP32(UART2) 로 전환 | UDP 서버 연동 목표 | 확정 |
| D4 | ESP32 역할 = **프로토콜 변환 게이트웨이** (터널링 아님) | 최종적으로 ESP32 가 STM32 역할까지 흡수 예정 | 확정 |
| D5 | ESP32 ↔ 서버 = ~~JSON~~ → **바이너리** | 패킷 크기·파싱 부담, 임베디드 친화 | 확정(번복) |
| D6 | UDP 는 **2byte SIZE + CRC16-MODBUS** | 오류 검출 강화, 확장성 | 확정 |
| D7 | UART 는 **1byte SIZE + `255-합` 체크섬 유지** | STM32 코드 무변경 | 확정 |
| D8 | 헤더에 **Device Type + Device ID** 포함 | 서버 한 포트에서 AOS/GFC/Control 다중 수용 | 확정 |
| D9 | DTYPE: 1=AOS, **2=GFC(현재 장비)**, 3=Control / DID: **1~20** | 사용자 지정 | 확정 |
| D10 | 실수값은 **4byte IEEE-754 float**, `memcpy` 로 구조체 직접 사용 | 개발 편의, 스케일링 오류 방지 | 확정 |
| D11 | UDP 명령코드를 **`0x30` 부터 연속 배치** (제어+설정 통합) | 관리 단순화 | 확정 |
| D12 | 하향(서버→ESP32)은 **ACK 동봉 방식** 기본 | NAT/공유기 뒤에서 포트포워딩 없이 제어 | 확정 |
| D13 | 핀: **GPIO32 RED / GPIO33 GREEN / UART2** | 사용자 지정 | 확정 |
| D14 | LED 2개로 서버 연결 상태 / 자동 동작 상태 표시, **타이머 구동** | 사용자 지정 | 확정 |
| D15 | STM32 자동 송신 여부 확인 후, 없으면 **1초 주기 폴링** | 사용자 지정 (기존 코드의 약점 보완) | 확정 |
| D16 | 가스 제어 핵심 설정 = **초기 주입시간 + 10분 주기 주입시간** | 사용자 지정 | 확정 |
| D17 | 자동 농도조절은 난이도 높음 → **개루프 우선, 예측형까지가 1차 범위** | 응답 지연이 큼 | 확정 |

> **번복 이력 주의**: D2(명령코드 재배정)와 D5(JSON)는 한 번 반영했다가 되돌린 결정이다.
> 문서에는 최종 상태만 반영되어 있다.

## 5. UART 규격 요약 (STM32 ↔ ESP32) — 변경 없음

상세: [`RS232_Protocol.md`](./RS232_Protocol.md)

```
+-------+-------+--------+----------------+----------+
|  STX  |  CMD  |  SIZE  |   DATA[SIZE]   | CHECKSUM |
| 0x02  | 1byte | 1byte  |    N bytes     |  1byte   |
+-------+-------+--------+----------------+----------+

CHECKSUM = 255 - ((CMD ~ DATA 합) mod 256)      ※ STX 제외
```

| CMD | 이름 | DATA |
|---|---|---|
| `0x70` | PUMP_VALVE_SET | 3 byte — Pump1/2/3 (0/1) |
| `0x71` | PUMP_VALVE_QUERY | 요청 0 / 응답 3 byte |
| `0x72` | SENSOR_PUMP_VALVE_QUERY | 요청 0 / 응답 11 byte |

**`0x72` 응답 11 byte**

| Offset | 내용 |
|---|---|
| 0~2 | Pump1/2/3 상태 |
| 3~4 | CH1 예약 (eCO2 추정, 미사용) |
| 5~6 | **CH1 TVOC raw** (u16 LE) |
| 7~8 | CH2 예약 |
| 9~10 | **CH2 TVOC raw** (u16 LE) |

- 115200 / 8-N-1, 프레임 타임아웃 약 50 ms
- 검증된 프레임 예: `02 70 03 01 00 00 8B`, `02 71 00 8E`, `02 72 00 8D`
- ESP32 는 5V tolerant 아님 → STM32 TX 레벨 확인 필수

## 6. UDP 규격 요약 (ESP32 ↔ 서버)

상세: [`ESP32_PRD.md`](./ESP32_PRD.md) 6~11장

### 6.1 패킷

```
 0     1       2      3     4   5     6   7    8 ...      N   N+1
+-----+-------+------+-----+-----------+-----------+--------+---------+
| STX | DTYPE | DID  | CMD |   SEQ     |   SIZE    |  DATA  |  CRC16  |
| 0x02|  1B   |  1B  | 1B  |  2B (LE)  |  2B (LE)  |   N B  | 2B (LE) |
+-----+-------+------+-----+-----------+-----------+--------+---------+
전체 길이 = 10 + SIZE,  최대 512 byte 권장
```

- 전 필드 **Little Endian**
- **CRC16-MODBUS** (poly `0xA001`, init `0xFFFF`), 범위 = offset 1 ~ (7+SIZE), **STX 제외**
- 헤더 8byte → DATA 시작이 4의 배수 → payload 내 float 4byte 정렬 유지 → `memcpy` 직결

### 6.2 주소

| DTYPE | 1=AOS, **2=GFC(본 장비)**, 3=CONTROL, 255=BROADCAST |
|---|---|
| **DID** | **1~20 정상**, 0=미할당, 21~254 폐기, 255=BROADCAST |

`(DTYPE, DID)` 가 시스템 전역 유일 주소. 양방향 모두 **장비의** 값을 적는다.

### 6.3 명령 코드

| CMD | 이름 | SIZE | 대응 UART |
|---|---|---|---|
| `0x01` | HELLO | 64 | — |
| `0x02` | ACK (+ 명령 동봉) | 4+α | — |
| `0x03` | CRES (명령 결과) | 8 | — |
| `0x04` | EVENT | 16 | — |
| `0x05` | PING | 0 | — |
| `0x06` | DISCOVER | 0 | — |
| `0x30` | PUMP_SET | 4 | **`0x70`** |
| `0x31` | PUMP_QUERY | 0 / 4 | **`0x71`** |
| `0x32` | SENSOR_DATA | 0 / 52 | **`0x72`** |
| `0x33` | SENSOR_BULK (오프라인 버퍼) | 4+16n | — |
| `0x34` | **SRC_SET (주입 설정)** ★ | 16 | — |
| `0x35` | AUTO_SET (자동 농도조절) | 28 | — |
| `0x36` | CFG_SET | 32 | — |
| `0x37` | NET_SET | 112 | — |
| `0x38` | TIME_SET | 4 | — |
| `0x39` | CFG_QUERY | 0 | — |
| `0x3A` | SYS (reboot/save/factory/OTA) | 4+α | — |

### 6.4 핵심 페이로드 2개

**`0x32` SENSOR_DATA (52 byte)** — 모든 float 4byte 정렬

```c
#pragma pack(push,1)
typedef struct {
    uint32_t ts;                        // 0
    float    volt1, volt2;              // 4, 8    [V]
    float    ctrl, slope, sv;           // 12,16,20
    float    src_remain, src_elapsed;   // 24, 28  [s]
    uint32_t uptime;                    // 32
    uint16_t raw1, raw2, co2_1, co2_2;  // 36,38,40,42
    uint8_t  pump1, pump2, pump3, flags;// 44,45,46,47
    uint16_t err;                       // 48
    int8_t   rssi;                      // 50
    uint8_t  rsv;                       // 51
} sensor_data_t;   // 52
#pragma pack(pop)
```

**`0x34` SRC_SET (16 byte)** — 가스 제어의 핵심 설정값 ★

```c
typedef struct {
    uint8_t enable;        // 0   1=시작, 0=정지
    uint8_t rsv[3];
    float   init_on_sec;   // 4   ★ 초기 주입시간 [s], 기본 30.0
    float   cycle_on_sec;  // 8   ★ 10분 주기 주입시간 [s], 기본 1.0
    float   period_sec;    // 12  주기 [s], 기본 600.0
} src_set_t;   // 16
```

동작: `enable=1` → Pump1 On 고정 → `init_on_sec` 동안 Pump2/3 연속 On →
이후 `period_sec` 마다 `cycle_on_sec` 동안 On 반복.

### 7.1 LED 표시 규격

100 ms `esp_timer` 가 **16비트 패턴을 1비트씩 시프트** (1회전 1.6초). 메인 로직 블로킹과 무관하게 동작.

| 패턴 | 값 |
|---|---|
| OFF / ON | `0x0000` / `0xFFFF` |
| SLOW (0.8s 주기) | `0xFF00` |
| FAST (0.2s 주기) | `0xCCCC` |
| BLINK2 | `0x0005` |

**RED(32)**: 에러=BLINK2 (최우선) / **자동제어=ON** / 주입만=SLOW / 대기=OFF

## 8. STM32 자동 송신 확인 + 폴백 폴링 (FR-2)

기존 PC 코드의 약점(자동 push 전적 의존)을 보완하는 요구사항.

```
┌─────────────┐  3초 내 자동 프레임 수신   ┌──────────────┐
│  BOOT/관찰   │──────────────────────────>│  AUTO_PUSH   │
└─────────────┘                            └──────────────┘
       │ 3초 경과, 수신 없음                    │ 15초 미수신
       v                                       v
┌─────────────┐   요청 없이 프레임 도착        ┌──────────────┐
│   POLLING   │<──────────────────────────────│   (전환)      │
│ 1초 주기 0x72│───────────────────────────────>              │
└─────────────┘   3회 무응답 → LINK_LOST       └──────────────┘
```

상태는 `flags` bit7(`auto_push`), `err` bit10(폴링 모드), `EVENT 0x32 POLL_MODE` 로 서버에 보고.

## 9. 자동 농도조절 — 난이도와 접근법

### 9.1 왜 어려운가

| 요인 | 내용 |
|---|---|
| 큰 데드타임 | 펌프 On → 센서 반응까지 수십 초 지연. 단순 On/Off 는 반드시 진동 |
| 긴 시상수 | 확산·희석이 분 단위. 한 주기 결과 확인 전에 다음 결정을 해야 함 |
| **비대칭 응답** | 올리는 건 주입으로 가능, **내리는 건 자연 감쇠에 의존** → 오버슈트 회복이 매우 느림 |
| 센서 드리프트 | TVOC baseline 이동 → 절대값 기준 제어 신뢰도 낮음 |
| 낮은 샘플링 | 5초 간격이라 짧은 On 구간이 샘플 사이로 지나감 |

### 9.2 단계적 접근

| 단계 | 방식 | 범위 |
|---|---|---|
| **A. 개루프** | `init_on_sec` + `cycle_on_sec` 고정 | **1차 목표** — 재현 가능한 주입 프로파일 |
| **B. 예측형 On/Off** | `ctrl + slope × lead` (기존 코드 방식) | **1차 범위 포함** |
| C. PI + anti-windup | 주기당 On 시간 연속 조절 | A/B 실측 후 판단 |

### 9.3 튜닝 절차

1. `auto` Off 상태로 `init_on_sec` 을 30 / 60 / 120초로 바꿔 스텝 응답 기록
2. 곡선에서 **데드타임 L**, **시상수 T**(63% 도달) 측정
3. `lead_sec ≈ L + T/2` 로 시작 (기본 120초는 임시값)
4. `deadband` = 노이즈 진폭의 2배 이상
5. `ema` 0.2 부터, 노이즈 남으면 0.1
6. `max_on_sec` = 1주기 내 목표 초과하지 않는 최대 시간

### 9.4 필수 안전장치

- `max_on_sec` 상한, `min_off_sec` 이내 재On 금지
- 센서 raw 0/4095 고착 N초 → 자동제어 정지 + 이벤트
- UART 링크 끊김 → 자동제어 정지, 펌프 안전측(Off)
- **서버 통신이 끊겨도 로컬 제어는 계속 동작** (네트워크는 제어 루프에 미포함)

2. 상향 패킷마다 소스 주소로 `0x02 ACK` 즉시 회신

6. `tx_interval × 3` 초 무통신 시 오프라인 표시

### 10.3 검증

- CRC16 벡터 — `ESP32_PRD.md` 10장 예제 4건과 일치
- float 바이트: `3.0f = 00 00 40 40`, `1.5f = 00 00 C0 3F`, `30.0f = 00 00 F0 41`, `600.0f = 00 00 16 44`
- `sizeof()`: sensor=52, src_set=16, auto=28, cfg=32, hello=64
- `SIZE` 경계값(0,1,512) 및 조작된 SIZE 폐기
- `SEQ` 65535→0 순환 시 중복 제거
- `DID` 0 / 21~254 폐기

- LED 6가지 상태 육안 확인
- 주입: `init=30, cycle=1.5, period=600` 2주기 이상 파형 확인

## 11. 검증용 스니펫

### 11.1 CRC16 / 패킷 생성 (Python)

```python
import struct

def crc16(d):                      # CRC-16/MODBUS
    c = 0xFFFF
    for b in d:
        c ^= b
        for _ in range(8):
            c = (c >> 1) ^ 0xA001 if c & 1 else c >> 1
    return c

def build(dtype, did, cmd, seq, data):
    body = bytes([dtype, did, cmd]) + struct.pack('<HH', seq, len(data)) + data
    return bytes([0x02]) + body + struct.pack('<H', crc16(body))   # STX 제외 CRC

# 예) GFC #1 주입 설정: init=30s, cycle=1.5s, period=600s
p = build(2, 1, 0x34, 90, bytes([1,0,0,0]) + struct.pack('<fff', 30.0, 1.5, 600.0))
print(" ".join(f"{x:02X}" for x in p))
# 02 02 01 34 5A 00 10 00 01 00 00 00 00 00 F0 41 00 00 C0 3F 00 00 16 44 D0 5D
```

### 11.2 UART 체크섬 (Python)

```python
def uart_cs(b):                    # b = CMD 부터 DATA 끝까지
    return 255 - (sum(b) % 256)

# 02 70 03 01 00 00 8B   (Pump1 On)
print(hex(uart_cs([0x70, 0x03, 0x01, 0x00, 0x00])))   # 0x8b
```

### 11.3 검증된 예제 패킷

| 용도 | 바이트열 |
|---|---|
| UART Pump1 On | `02 70 03 01 00 00 8B` |
| UART `0x72` 요청 | `02 72 00 8D` |
| UART `0x72` 응답(예) | `02 72 0B 01 00 00 00 00 9A 09 00 00 66 06 72` |
| UDP PUMP_SET 전체 On | `02 02 01 30 4D 00 04 00 01 01 01 00 9D 19` |
| UDP SRC_SET(30/1.5/600) | `02 02 01 34 5A 00 10 00 01 00 00 00 00 00 F0 41 00 00 C0 3F 00 00 16 44 D0 5D` |
